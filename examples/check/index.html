    check

    Open in the player, with the keyboard and gamepad reference.

    The check sample, in Go.

    A port of sdk/sample/check/main.c: bouncing balls over a cleared background, the count adjustable with the d-pad, with the sound data read off the disc. It exists to show the Go bindings carrying a real program rather than a hello world, and to put the CD path, the controller and a few hundred sprites through the same code the C sample uses.

    Two deliberate differences from the original:

    • The CD waits are bounded. The C sample spins in "while ((cnt = CdReadSync(1, 0)) > 0)" with no limit, so running it without the files present hangs before it has drawn anything.
    • Sound is only started if the VAB actually loaded. The C sample calls SsSeqSetVol and SsSeqPlay with whatever handle it has, including the zero left behind when the transfer failed.

    Nothing allocates after startup. With no collector running, anything allocated in the frame loop would never be reclaimed.
